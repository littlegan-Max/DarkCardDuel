## 你要做的事

实现 `NetClient` 这一个类，让「大厅」和「对战」能连上服务器。

**不用改**：界面、规则、卡表、AI。
**可能要改**：`server/server.py`（如果你打算连服务端协议一起重做，见文末「协议去哪看」）。

## 为什么清空，而不是让你在旧代码上改

旧的客户端连接是这套：

- 传输：明文 `http://`，没有 TLS
- 凭据：token 明文写在 `user://net_profile.cfg`
- 服务端：默认 `--host 0.0.0.0`，任何能连上端口的人都能打
- 认证：只凭一个 token，没有别的

结果是：同一局域网内抓个包就能冒充任意玩家；房主那台机器上的服务器
能看到所有人的 token 和出牌。这不是补两行校验能解决的，所以整段交出去重写，
不留旧实现给人抄。

## 必须保留的接口

大厅和对战是靠这些名字跟联机层对话的，**签名可以加参数，不能改名或删**：

```gdscript
# 信号
connected_ok
disconnected(reason: String)
event_received(evt: Dictionary)
command_result(cmd: String, res: Dictionary)
online_count_changed(count: int)
rooms_changed(rooms: Array)
version_error(message: String)
server_updated(rules_version: String)
client_update_available(server_version: String)
server_outdated(server_version: String)

# 字段（大厅、对战、匹配都直接读）
token / player_id / player_name
host / port
rules_version / local_game_version / server_game_version

# 方法（现在都是空体）
set_server(host, port) / server_url() / has_identity() / clear_identity()
send() / api() / start_polling() / stop_polling() / shutdown()
on_scene_transferred() / cmd_req_in_tree()
register(name) / login() / rename_player(name)
create_room(turn) / join_room(code) / leave_room() / start_room(room_id, turn)
matchmake() / cancel_match() / match_status() / list_players() / list_rooms()
add_friend(name) / remove_friend(id) / list_friends() / invite_friend(id, room_id)
remove_member(room_id, target) / set_presence(state) / play_card(room_id, card)
```

### 六条契约

1. **登录**：成功后发一条 `command_result`，cmd 分别是 `"register"` / `"login"`，
   res 里带 `ok=true`，并把 `token` / `player_id` / `player_name` 三个字段填好。
2. **事件**：服务器推来的一切走 `event_received(evt)`。`evt.type` 的取值见
   `server/server.py` 顶部的协议表。
3. **回执**：`command_result(cmd, res)` 里的 `cmd` 名必须和指令名一致，
   大厅是 `match cmd:` 分支处理的。
4. **对战**：`play_card(room_id, card_id)` + 上面的事件（`turn` / `state` / `game_over`）。
5. **失败要发信号**，不要静默 —— 大厅的状态条、版本提示全靠这些信号。
   连不上、被踢、规则或协议版本不一致，各有对应信号。
6. **开关**：做完把文件顶部的 `TRANSPORT_READY` 改成 `true`。端到端联机测试
   认这个开关，见下面「验收」。

### 版本握手别改方向

`_check_version()` 和 `_ver_lt()` 是纯逻辑，没清空，`tools/test_scene_nav.gd`
在测它。语义是：

- 服务器比客户端**旧** → 发 `server_outdated`，提示「服务器该更新」（服务器会自动更新）
- 客户端比服务器**旧** → 发 `client_update_available`，提示「你该更新客户端」

这两句以前接反过一次，玩家被误导着去重装客户端，所以有专门的回归测试。

## 安全底线（这次重写的核心）

具体方案你定，但下面几条建议别退让，否则等于换了个 UI 继续裸奔：

1. **传输必须 TLS**。客户端要校验证书，不要为了"本地调试方便"加一个
   `verify=false` 的开关然后忘了删。
2. **token 不要明文落盘**。能做到系统凭据存储（钥匙串 / DPAPI / Keystore）最好；
   做不到就只放内存，每次启动重新登录。
3. **不要沿用 `user://net_profile.cfg`**，旧 token 就留在玩家机器上，别读了。
4. **身份别用昵称**。昵称可以重名、可以随时改，现在只适合当显示名。
5. **指令带序号 + 服务端只认递增**，防重放。现在的协议里有 `seq`，可以接着用。
6. **服务端别默认 `0.0.0.0`**。要么显式传 `--host`，要么在文档里写清楚
   "这个端口会被公网访问"。

## 怎么跑

```bash
# 客户端（编辑器直接跑）
godot --path darkcard

# 服务器（纯标准库，不需要装依赖）
python3 darkcard/server/server.py --port 8737

# 探活
curl -s http://127.0.0.1:8737/api/health
```

环境：Godot **4.7.2 标准版**（非 .NET）+ 对应导出模板；Python 3.8+ 就能跑服务器
（只用标准库，不需要 `pip install`）；训练与对拍脚本按 CI 的要求是 3.11+ + `numpy`，
**联机链路本身不需要 numpy**。

⚠️ 脚本里的 Godot 路径默认写死成这台机器的 `D:/Godot_v4.7.2-...`。
换机器先设环境变量，否则 `verify.sh` 和联机测试都会找不到引擎：

```bash
export GODOT="/你的路径/Godot_v4.7.2-stable_win64.exe"   # Windows Git Bash 用 /d/... 也行
```

```bash
# 全量门禁（卡表 → 单测 → 对齐 → 对拍 → 不变量 → 服务器自测 → 联机端到端）
bash darkcard/train/verify.sh
```

打满一局，逐回合把客户端的本地重放结果和服务器的状态快照对账。**这一项真跑通
才算接完**，SKIPPED 不算通过。

## 已经踩过的坑

- **新增 `class_name` 后先刷一次类缓存**：
  `godot --headless --path darkcard --editor --quit`，
  否则直接跑会报「Identifier "XXX" not declared」。
- **`test_scene_nav.gd`** 会点「联机对战」→ 大厅 → 进对战 → 回主菜单，
  它要求 `NetClient` 至少保留 `token` / `player_id` / `has_identity()`，别删。
- **`_enter_battle()` 要把 client 节点一起转到对战场景**（`SceneRouter.swap` 的第三个参数），
  否则进对战就是「连着但收不到消息」。这段没动，别改坏。
- 现在拉事件用的是**长轮询**（服务器 hold 住连接，有事件才返回），
  换成 WebSocket 完全可以，只要事件格式对得上。

## 协议去哪看

如果打算换协议（比如上 WebSocket / 换鉴权），先跟作者确认：
