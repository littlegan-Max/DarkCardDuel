## 2. DrawCall 超预算的处置

本机实测 DrawCall 172，预算线 100（03 文件）。归因：**50 张卡牌全部实例化**，每张卡有插画 + 边框 + 文字等多层 Control。

处置方案（按性价比排序）：

1. **先做节点池**：只保留可见的两行（约 12 张），其余回收复用 → 节点数与 DrawCall 大致按比例下降。
2. 插画合并为图集（AtlasTexture），减少材质切换。
3. 卡面边框改用单张九宫格贴图，替掉多层 StyleBox。

在这三项完成前，本条保持 ⚠️，不得作为正式发布依据。

## 3. 回滚方案

| 项 | 内容 |
|---|---|
| 版本保留 | 每次发布保留上一版 APK 与 EXE（`darkcard/build/archive/vX.Y.Z/`），不覆盖 |
| 回滚触发条件 | ① 崩溃率 > 1% ② 核心流程无法完成对局 ③ 规则结算与预期不符（可利用度异常） ④ 商店驳回 |
| 回滚操作 | ① 用上一版包覆盖安装（versionCode 需更高，或先卸载）② 服务端/配置侧把 `rules_version` 与 `strategy_version` 一起回退 ③ 公告 |
| 规则回滚 | 规则改动走 RFC，回滚以"规则文档版本号"为准：代码内 `rules_version` 字段必须与文档一致 |
| 策略回滚 | AI 策略由 `policy_net.json` 驱动，保留上一版权重文件即可回退（文件级回滚，无需重编译） |
| 验证 | 回滚后必须重跑 `bash train/verify.sh`（规则回归 + 对拍 + 不变量）并做一局人工验收 |
| 数据迁移 | 当前无存档与账号体系，回滚不涉及数据迁移；接入存档后需先补迁移函数再谈回滚 |

## 4. 应急开关

| 开关 | 位置 | 默认 | 作用 |
|---|---|---|---|
| `debug/force_card` | ProjectSettings | 空 | 强制 AI 每次出指定牌（复现某个对局分支） |
| `debug/verbose_log` | ProjectSettings | false | 结算日志输出更详细 |
| `debug/show_fps` | ProjectSettings | false | 顶部显示实时 FPS |
| `debug/hold` | 调试脚本 | false | 暂停自动对局，等人工出牌 |

正式包默认全部关闭，读取处统一在 `scenes/battle/battle_screen.gd` 顶部常量，无副作用。
