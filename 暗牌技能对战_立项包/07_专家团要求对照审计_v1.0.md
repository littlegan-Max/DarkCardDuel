# 专家团要求对照审计（v1.0）

> 审计对象：`darkcard/` Godot 4.7.2 工程（50 张牌 · 规则 2.1 垂直切片）
> 审计基准：银橙AI Godot 游戏开发专家团四角色规范（核心开发 / 性能调试 / 测试发布 / 设计总监）+ 各角色质量自查清单
> 审计日期：2026-10-25
> 结论一句话：**规则内核与数据驱动层做得比专家基线更高，但工程化外壳（脚本拆分、度量、CI、存档、平台层、发布闭环）明显欠账，属于"能玩但不符合交付规范"。**

---

## 0. 任务定性与所处阶段

| 项 | 内容 |
|---|---|
| 任务定性 | ①对既有工程做规范符合性审计 ②训练 AI 策略模型 |
| 所处阶段 | 阶段二（核心开发）主体已完成 + 阶段三（性能度量）**未开始** + 阶段四（测试发布）**只做了自动化层，真机层为 0** |
| 主责角色 | 审计：核心开发 + 性能调试 + 测试发布三角色自查清单合并核对；训练：核心开发（工具链） |
| 准出判断 | **不满足阶段三准入**（无基线数据）、**不满足阶段四准出**（无真机数据、无回滚方案） |

### 1.2 不符合（P0，必须补）

| # | 专家要求 | 现状 | 后果 |
|---|---|---|---|
| **P0-1** | 核心开发硬约束「单脚本行数超标时拆类或拆场景」 | `scenes/battle/battle_screen.gd` **1021 行**，承担 UI 构建、结算演出、日志、手势、计时全部职责 | 典型 giant script：改一处崩一片、无法拆分并行开发、无法单测 UI 分支 |
| **P0-2** | 性能调试铁律 1「先度量后动手」+ 自查「基线数据齐全（帧率/DrawCall/内存/包体/目标环境）」 | **只有纸面预算**（03 文件），无 FPS / DrawCall / 节点数 / 内存实测 | 违反最核心纪律；50 张卡全量实例化这类风险没有数据支撑 |
| **P0-3** | 性能调试自查「目标最低环境数据已覆盖」；QA 自查「目标环境真机数据已覆盖」 | **真机数据 0**：APK 刚导出，adb 无设备在线，模拟器未运行 | 无法回答"低端机能不能跑"，包体/内存/帧率全未验证 |
| **P0-4** | QA 自动化分层「单元测试：**GUT 或 WAT**」 | 用自研 headless runner（`tests/test_runner.gd`），**不是 GUT/WAT** | 覆盖面超基线，但不符合工具口径、无法直接接标准 CI、团队无法按规范接手 |
| **P0-5** | QA「自动化测试接入 CI，每次合入跑一遍，红灯不合并」 | `train/verify.sh` 已具备一键能力，但**无 CI 配置** | 门禁靠人自觉，回归无法强制 |
| **P0-6** | ui-config 三.1「存档结构带版本号与迁移函数」 | ~~**无存档系统**~~ → **部分关闭**：对手画像存档已落地（`OpponentStore`，schema v1 + 迁移链 + 损坏兜底 + 备份） | 对局过程本身不需要存档（实时对战）；设置项/战绩仍未落盘 |
| **P0-7** | ui-config 四.1「平台能力封装在平台层，业务侧无感」；核心开发自查「平台能力已封装隔离」 | **0 autoload、0 平台层** | 未来接广告/成就/排行榜/热更新会直接污染业务代码 |

### 本机性能基线（2026-10-25 · 战斗场景 · 10 秒 · 1651 帧）

| 指标 | min | avg | max | 预算 | 判定 |
|---|---|---|---|---|---|
| FPS | 165 | 165 | 165 | ≥ 60 | ✅ |
| DrawCall/帧 | 172 | 172 | 172 | ≤ 100 | ❌ **超预算** |
| 节点数 | 824 | 824 | 824 | ≤ 600 | ⚠️ |
| 静态内存 | 44.8MB | 45.5MB | 46.6MB | ≤ 200MB | ✅ |
| 脚本耗时 | 6.12ms | 6.27ms | 7.16ms | ≤ 4ms | ⚠️ |
| 物理耗时 | 0.03ms | 0.03ms | 0.17ms | — | ✅（无物理需求） |
| 卡牌实例数 | 50 | 50 | 50 | 虚拟化后 12 | ❌ 未虚拟化 |

**归因**：DrawCall 与节点数超线都来自"50 张卡全量实例化"（每张卡 = 插画 + 边框 + 文字多层 Control）。这是 A1 风险的量化。处置见 08 文件第 2 节：节点池 → 图集 → 九宫格边框。

**注意**：以上是 RTX 4060 笔记本数据，**不代表低端真机**。低端机数据仍缺（对应 A2）。

## 4. 风险与未决事项

| # | 风险 | 影响 | 处置 |
|---|---|---|---|
| A1 | 50 张卡全量实例化 | 低端机节点数与 DrawCall 可能超预算 | 待 P0-2 基线数据出来再定是否做 12 节点池虚拟化 |

| A3 | 规则文档原文未回写 | 文档与代码口径分叉，QA 无唯一基准 | 作者确认后按 06 补丁回写 v2.1 |
| A4 | 无音效 | 体验不完整 | 需确定音效方案（技能音效/环境音/UI 音）与产能 |
| A5 | 自研测试框架与 GUT 口径不一致 | 团队接手成本 | 二选一：迁移 GUT，或在文档中登记为"经批准的偏离"并说明理由 |
