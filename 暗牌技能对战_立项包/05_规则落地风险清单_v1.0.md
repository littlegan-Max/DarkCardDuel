## 1. 已裁定（作者 2026-10-24）

### Q1 葵花宝典：出招者自己的后续费用减半

**裁定原文**：葵花宝典是出招者以后的 cost 减半。

| 项 | v2.0 文本 | 2026-10-24 裁定 |
|---|---|---|
| 受益方 | 对方（"对方整局所有技能消耗×50%"） | **出招者自己** |
| 效果 | 让对手变便宜（逻辑上自伤） | 让自己后续所有牌半价（经济引擎） |

> 这不是笔误，是**卡的定位反转**：从"莫名其妙的 debuff"变成"5 费 + 4 连招的后期引擎"。v2.1 必须同时改技能表、B10、C42 三处描述。

**落地口径**

- `COST_MULT{ ratio: 0.5, scope: self }`，只作用于**葵结算之后**出的牌，不影响葵自身（已付 5）。
- 对可变 cost 无效（战术核弹不受影响，C42 保留）。
- 不可叠加、不可被净化（C42 保留）。
- 费用落到 0.5 步进：1→0.5、2→1、3→1.5、4→2、5→2.5、7→3.5。
- 元首の愤怒把意大利炮降到 2 后再减半 → 1；此时护身符的 2~3 区间**挡不住它**。
- 吸的"实际花费"按减半后结算（例：葵后长攻实际 1.5，吸得 1.5）。
- 护身符阈值按减半后判定：2.5 / 3 可挡；1.5 / 3.5 不可挡（C43 不变）。
- **龟派交互**：葵是自增益，被龟派转化后 **B 获得减半、A 的葵作废**。适配表该行必须改。
- 葵的 4 连招前置是公开信息，龟派（0 费）是最强反制；A 铺垫 4 回合的 5 费投资可被一次读中夺走。
- **更常见的风险是可被列**：葵可被 1 费小镖挡下，按 B1"附带效果不再结算"，5 费 + 4 连招直接归零。若实测出场率过低，优先把葵的可被列改为空，而不是降价。

**平衡判断**

- 收入模型：正常 1 运/回合。4 段连招（中防→吸→运→超级吸，合计 1 费）走完到第 5 回合手上约 1 运；再攒约 4 回合才够 5 费，**葵最早第 9–10 回合才能打出**（有吸/勾魂偷运可提前 1–2 回合）。
- 回本：葵后按每回合 3 费支出省 1.5，回本还要约 4 回合 → **第 13–14 回合才净赚**。中位对局 8 回合，意味着普通局里几乎打不出来。
- 真实风险是**两端**：普通局"太贵打不出"（更可能），长局/优势局"打出来后加速"。监控**打出率**（< 5% = 太贵）与**打出后胜率**（> 70% = 太强）。
- 调法：太贵优先动费用或连招长度（5→3 费，或连招 3 段），**不要动减半倍率**；太强再改"仅 ≤3 费牌"或"持续 3 回合"。
- 连带风险：盾 4→2、3→1.5，可能催生"葵 + 无限盾"的拖延流，需与长局守护（D4）一起观察。

**行动项**：改技能表/B10/C42 文案 → 改适配表葵行 → 改 `COST_MULT` 的 scope → 用例 `test_c42_kui_self_cost_half`、`test_b13_turtle_steals_kui`。

### Q2 战术核弹：当扣 4，不足 4 也能出，扣到 0

**裁定原文**：核弹 0-4 你就当扣 4 个运，但不够 4 个也可以出，运扣到 0 个。

**落地口径**

| 项 | 口径 |
|---|---|
| 费用类型 | `cost_kind = all_in`，名义费用 **4** |
| 实际扣除 | `pay = min(max(运, 0), 4)`；运不足则扣到 0 |
| 付费时点 | **出牌锁定瞬间**；后续负运/比心/勾魂不回算 |
| 合法性 | **永不拦截**：0 运也能出（与普通费用牌最大的区别） |
| 伤害 | 固定 `-2.2`（与付费无关） |
| 盾 | 需 2 张（C38 不变） |
| 连招 | 运→运→运→运；用后连招进度清除 |
| 护身符 | **按费用 4 判定** → 不在 2~3 区间，**挡不住** |
| 葵花宝典 | 仍属"可变 cost" → **不作用**（C42 保留） |
| 吸 | 核弹可被列无"吸" → 不交互 |

**边界（实现保护）**：运为负时，字面"扣到 0"会变成"回填 N 点运"，等于费用牌给人送资源。实现按 **付费下限 0、不抬升负数**（运 -3 → 仍 -3，付费 0）。若你要字面执行（负数也归零），一句话可改。

**设计影响**：从"0~4 自选"变成"全押"——你有多少（最多 4）就押多少。理性玩家仍会在 4 运时出，但被吸/勾魂压运后不再被彻底卡死。费效从"0.55–∞"收敛为"按 4 计 0.55"，低费打出反而更赚，这是被压运后的补偿。

**行动项**：技能表费用栏改为"4（不足可出，扣至 0）" → `cost_kind` 增加 `all_in` → 用例 `test_q2_nuke_all_in`。

### Q4 桃园结义：双方都奶

**落地口径**

- 2 人局：**双方各 +0.5**（出牌者与对手都加）。
- 治疗不受减益；加血可超过 1（A3）。
- 龟派转化后，B 使用桃园仍是"双方各 +0.5"，**转化对结果无差异**，记录为已知无差异。

| 项 | 值 |
|---|---|
| 自己净收益 | +0.5 |
| 对手净收益 | +0.5 |
| **相对血差** | **不变（0）** |
| 汇率（对自己） | 0.25 血/运 |

**设计定位**：不是治疗牌，是"把双方同时推离斩杀线"的拖延牌。落后方打出会压缩相对差距（0.2 vs 1.0 → 0.7 vs 1.5），领先方打出等于自损。

### Q6 小数：全局允许

**落地口径**

- 血量：1 血 = 100（0.01 精度）。
- 运：1 运 = 10（0.1 精度），允许 0.5。
- 全部用整数定点比较，**禁止 float**（回放哈希必须稳定）。
- 显示：整数不显示小数，半点显示一位（`3.5`）。
- 合法性 `yun >= cost` 精确比较；吸的实付、护身符阈值、比心下限全部按小数参与（C43）。

**行动项**：`DuelState.yun` 注释改"1=10" → 用例 `test_q6_half_cost_payment`。

### Q7 毒药百分比：向下取整到 0.01

**落地口径**

```gdscript
# hp 为定点（1 血 = 100）
var dmg := (hp * 80) / 100        # 整数除法即向下取整
var dmg_yun_blocked := (hp * 40) / 100
```

| 场景 | 结果 |
|---|---|
| 1.28 血 × 80% | 1.024 → **1.02** |
| 1.28 血 × 40%（运挡） | 0.512 → **0.51** |
| 0.05 血 × 80% | 0.04（不为 0，仍致死） |

理由：向下取整对防守方略有利，避免"差 0.004 血被斩杀"的观感争议。血条显示 2 位，日志显示 3 位。

**行动项**：用例 `test_q7_poison_floor_rounding`。

### Q9 比心：对方 -5 仍为 -5

**落地口径**

```gdscript
# yun 为定点：-30 = -3.0
func apply_bi_xin(yun: int) -> int:
    return maxi(yun - 20, mini(yun, -30))
```

| 对方当前运 | 比心后 |
|---|---|
| 0 | -2 |
| -2.5 | -3（只减 0.5，撞下限） |
| -3 | -3 |
| -5 | **-5（不变）** |

**关键断言**：比心**永远不能提升**对方运。错误的 `max(yun-2, -3)` 会把 -5 抬到 -3，等于给对手回 2 点运。

**行动项**：用例 `test_c26_bixin_no_raise`。

## 11. 引擎自检抓到的 3 个 bug（2026-10-25）

训练用的 Python 引擎与 GDScript 引擎做**随机对拍**时（同一批动作序列两边跑，逐字段比对），顺带审出三处真 bug。三条都会改变对局结果，不是日志瑕疵：

| # | 严重等级 | 症状 | 触发场景 | 修复 |
|---|---|---|---|---|
| E1 | **严重** | 盾的 `shield_cost` 靠"本回合对方那张牌"反查 | 自己中 dot 致死、而对方本回合出的是核弹 → 被要求 **2 张盾**，实际 dot 只该吃 1 张。反向也可能少算 | 伤害事件自带 `need` 字段，盾阶段直接读，不再反查 |
| E1 | 盾的 `shield_cost` 靠"本回合对方那张牌"反查 | 自己中 dot 致死、而对方本回合出的是核弹 → 被要求 **2 张盾**，实际 dot 只该吃 1 张。反向也可能少算 | 伤害事件自带 `need` 字段，盾阶段直接读，不再反查 |
| E2 | 一般 | 三棱镜被挡的 -0.2 直接改血量 | 绕过伤害事件 → **不触发盾保命**、不进伤害日志、不被酒免疫 | 改为写进 `damage_events`，走正常伤害管线 |
| E3 | 严重（训练侧） | 训练推演（probe）的终局没给胜负 | 值函数学不到"这一手直接把对手打死"，策略只看血量差 → 短视 | probe 遇到终局直接返回 ±1 |

**E1 的回归用例**：自己 0.2 血 + 1 张 dot + 1 张盾，对方出核弹被觉醒中防挡下 → 必须活下来（hp 回到 0.2）。这条用例在旧逻辑下失败（hp=0，判负），已验证。

### 双引擎对拍：以后改规则必须跑

|---|---|---|

### 这一轮的方法学收获

1. **不变量比用例更早发现问题**。第一版不变量检查器自己写错了（把 dot 当成"自己出的牌"而非"对方挂的"），修完检查器后 6000 局才干净。**检查器也要先验证**，否则会被一堆误报淹没。

### E9：策略网络的输出层被套了 ReLU（最严重的一个）

**严重等级：阻塞**

| 项 | 内容 |
|---|---|
| 严重等级 | **阻塞** |
| 症状 | `PolicyNet._dense()` 对所有层都做 `relu`，**包括输出层**。负 logit 全被截成 0 → softmax 后分布接近均匀 → 训练好的策略进游戏后退化成"随机乱出" |
| 为什么危险 | 这类 bug **不会报错**，表现只是"AI 好像没变聪明"。如果没有数值比对，要等到大量对局统计才会发现 |
| 发现方式 | 用固定随机权重 + 固定输入，跑一遍 Python 前向与 GDScript 前向，比对 51 个输出概率。首轮最大偏差 **4.4e-4**，打印中间层发现 GDScript 的 `logits[:3] = [0, 0, 5.62]` 而 Python 是 `[-4.58, -1.46, 5.62]` |
| 修复 | 抽出 `_linear()` 给输出层用，隐藏层继续用 `_dense()`（ReLU）。修复后最大偏差 **0.000000** |
| 固化 | `tools/test_policy_net.gd` + `tests/policy_net_ref.json`，已加入 `verify.sh` |

**参考值生成也有坑**：第一版参考数据用"未取整权重"算期望值，而导出的是保留 6 位小数的权重，比对出来 4.4e-4 的差异其实是**取整误差**，不是实现误差。改成"先取整、再用取整后的权重算参考值"才是有效比对。

## 13. Q24 定案：神之龟派的翻倍范围（2026-10-25 实测确认）

规则原文只写"所有 ±血量、±运 的数值翻倍"，但 50 张牌里有三类效果既不是固定血量也不是固定运。这一条之前一直没被压到（2 人局要凑齐"觉醒中防→超级吸→强化运"三张前置才能出神之龟派）。已用 `tools/probe_kui_edge.gd` 逐个实跑。

### 结论：翻倍只作用于"牌面写死的固定 ±血量 / ±运"

| 类别 | 牌 / 效果 | 是否翻倍 | 理由 |
|---|---|---|---|

## 14. 【未执行 · 待作者决定】高费牌可达性问题（2026-10-25 发现）

> 本节仅作为**提案**保留，等作者明确指示才动。

### 问题：4 张牌是"死内容"

看 30 局真实对局日志（`train/watch_games.py`）发现：AI 200 局只用到 32/50 张牌，
18 张从未出现——其中 **意大利炮、六神、六飞、葵花宝典、元首の愤怒、盾** 这 6 张高费牌，
以及 **龟派、神之龟派、向运葵、究掐、战术核弹** 这 5 张长连招牌。

根因不是 AI 策略压制，而是**经济上不可达**：

1. 运收入是每回合 +1，出"强化运"净 +1/回合 → 攒 5 运要 5 回合；
2. 而对手每回合能打 0.2~0.5 伤害，起手 1.0 血 → **5~6 回合就把你打死**；
3. 于是 4 费以上的牌永远打不出来。
4. 更严重的是：按 GDD 第 7 章的费效基准线 `D* = 0.55 + 0.42C`，
   意大利炮 7 费只打 3.0 伤害 → 3.0/3.49 = **低于基准 14%**。
   **AI 不出它是对的，这张牌在数值上就不该出。**

结论：这 6 张牌不是"AI 打不出来"，是**内容本身不成立**。必须改数值。

### 提案（未执行，等作者拍板）

| 牌 | 原 | 改 | 理由 |
|---|---|---|---|
| 强化运 | 1 费 +2 运 | 1 费 **+3 运** | 净攒运 +1/回合 → **+2/回合**，高费牌 2~3 回合可达 |
| 意大利炮 | 7 费 -3.0 | **5 费** -3.0 | D*(5)=2.65 → 3.0 伤害 **+13%**，仍是"大招"；7 费时 -14% 永远不该出 |
| 六神 / 六飞 | 5 费 -3.0 | **4 费** -3.0 | D*(4)=2.23 → **+35%**，但被运/中防克制（真伤 0.5 照掉），仍是赌博牌 |
| 葵花宝典 | 5 费 | **3 费** | 它给的是"后续费用减半"，价值极高但 5 费代价过大；3 费才可能在连招铺好后落地 |
| 元首の愤怒 | 4 费 | **3 费** | 与炮联动，3 费更顺；削成 2 费的炮仍落在护身符 2~3 区间（C18 不变） |
| 盾 | 首次 4 / 之后 3 | 首次 **3** / 之后 **2** | 4 费买一次免死太贵 |

改后费用分布：0 费 14、1 费 12、2 费 9、3 费 10、4 费 4、5 费 1（原本有 7 费档）。

### 连带影响（若将来执行）

- 规则文档（第六部分技能表）里这 7 张牌的费用需要同步。
- 运经济变化会让平均对局回合数下降（实测 7.1 → 5.9 回合），需要复核 03 文件的时长模型。

### 不改规则的情况下，AI 怎么用上这些牌

规则不动的前提下，可行的做法只有"AI 侧"手段（都不碰规则）：

1. **多样化层**（`train/variety_ai.py`，已实现）：随机挑冷门牌当临时目标，
   达不成就随机准备（攒运 / 铺连招前置 / 随便打一张），目标只维持 1~3 回合。
2. **温度采样**（`LearnedAI.TEMPERATURE = 1.4` + `EXPLORE = 0.08`）：把策略分布压平，
   避免同一局面永远出同一张牌。
3. 代价要说清楚：**5~7 费牌在当前经济下天然罕见**（要攒 4~7 运，而对手 5 回合能打死你），
   所以"几十局内看到每张技能都用过一次"在不改规则的前提下**做不到全覆盖**，
   只能做到"常见牌全覆盖 + 贵牌偶尔露面"。这是数值设计的结果，不是 AI 的缺陷。

### 15.4 顺带定下的两个判序（本批新增的规则交叉点）

| 交叉 | 判序 | 理由 |
|---|---|---|
| 比大小 × 酒 | 先比大小（决出只有哪方生效），再对被判生效的每一组套酒的 ≤1 免疫 | 比大小决定"谁的伤害存在"，酒决定"存在的伤害免不免"；反过来的话，被零化的一方还得靠酒才不挨打，逻辑倒置 |
| 比大小 × 真伤 | 真伤照旧穿过反制（B9），但**照样参与比大小**，输了会被零化 | 例：六飞被觉醒中防挡下时，真伤 0.5 输给反弹 0.8 → 真伤也不掉 |

另有两点已确认无需处理：三棱镜的 k 在 1v1 下恒 ≥ -1，公式值不会为负（不会出现"负伤害被零化"）；核弹 `all_in` 扣费与比大小无关。

补记：核弹被觉醒中防挡下时，被挡的 2.2 不再造成伤害，反弹 0.8 是独立一笔（源=防方），比大小里天然站在防方一边。
