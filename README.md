# 暗牌技能对战（Dark Card Duel）

1v1 同时翻牌的读心卡牌游戏，**支持单机与联机**。50 张技能牌、10 阶段结算管线、
可被列反制、连招、dot、盾。Godot 4.7.2 + GDScript；
同一套规则另有一份 Python 镜像实现，用于自博弈训练**和联机服务器**。

> 规则与数值由作者拍板，代码只负责实现。任何规则改动都走「作者裁定 → 双内核同步 → 对拍」的流程。

## 下载

到 [Releases](../../releases) 取最新包：

- `暗牌技能对战.apk` — Android，调试签名。安装时需允许"未知来源"。
- `暗牌技能对战.exe` — Windows 单文件，双击即玩，无需安装。

## 玩法

每回合双方同时扣下并翻开一张牌，然后按固定十阶段结算：
翻转 → 龟派 → 护身符 → 扭转时空 → 反制 → 资源与状态 → 伤害互拼 → 盾保命 → 死亡判定 → 结算。

- 血 10 点（内部 1 血 = 100 定点）、初始 1 运，每回合 +1 运。
- 卡表里每张牌都有**可被列**（哪些牌能挡它），读对对手的出牌方向才能吃到反制收益。
- 伤害互拼不是各打各的：比的是**单回合对对方的伤害总量**，相同则互抵，不同则只有高的生效。
- 首回合只能出「运」。血量归零或代码杀即负。

## 联机

游戏主菜单分「单机对战」和「联机对战」。联机大厅里可以：

- **快速匹配** —— 两个人都点匹配，自动配对开局
- **开房间** —— 拿到 6 位房号给朋友，或从大厅的房间列表直接加入
- **在线人数** —— 大厅右上角常驻显示
- **自定义昵称** —— 昵称即身份，重开自动记住
- **加好友 / 邀请好友** —— 填昵称加好友（双向），然后一键邀请进本房间

### 服务器

服务器是**纯 Python 标准库**实现的（`darkcard/server/server.py`），零依赖、零安装，
整个目录只有几十 KB，直接拷到任何有 Python 3.8+ 的机器上就能跑。
协议走 HTTP，所以能穿过任意形态的端口映射 / 反代 / 隧道。

```bash
# 起服务器
python3 darkcard/server/server.py --port 8737

# 验证映射通不通
curl -s http://你的公网地址:公网端口/api/health
```

部署细节（上传、systemd、端口映射、更新流程、排查）见 [`darkcard/server/README.md`](darkcard/server/README.md)。

**以后更新了要不要重发服务器**：**不用**。服务器每 10 分钟查一次 GitHub Releases，
有新版自己下载、自己应用，对方完全不用参与。

服务器按改动落在哪一层分别处理：

| 层 | 文件 | 处理 |
|---|---|---|
| 规则层 | `engine.py`、`cards.json` | 热重载，不重启进程，不打断任何对局（正在打的那局按旧规则打完） |
| 进程层 | `server.py`、新增模块 | 等没人打牌时 `execv` 重启（PID 不变，systemd 无感） |
| 依赖层 | `requirements.txt` | 自动 `pip install` |

**只有客户端（APK/EXE）要你手动重发**——这是客户端分发的固有约束。
不过客户端连上服务器时会比对游戏版本，服务器比自己新时大厅会提示
「服务器已更新到 vX，建议更新后再来」，不会让你稀里糊涂地打一场。

规则版本 / 协议版本不符仍然是**硬拦截**（提示"请让服务器更新"），
不会让你打一局结果错乱的比赛。

### 架构：服务器权威 + 客户端本地重放

服务器只发「双方各出了什么牌」，客户端用**与单机完全相同的 GDScript 内核**
重放这一手，事件流与单机完全一致——所以 UI 的日志、动画、判定文案一行都不用改。
每回合客户端会把本地重放结果和服务器的状态快照对一次账，不一致立刻报警。

## 本地运行与构建

需要 Godot 4.7.2（标准版，非 .NET）与对应导出模板。

```bash
# 编辑器里直接跑
godot --path darkcard

# 导出
godot --headless --path darkcard --export-debug  "Android"        "$PWD/darkcard/build/DarkCardDuel.apk"
godot --headless --path darkcard --export-release "Windows Desktop" "$PWD/darkcard/build/DarkCardDuel.exe"
```

## 验证

```bash
bash darkcard/train/verify.sh          # 卡表 → 单测 → 对齐 → 特征 → 对拍 → 不变量 → 联机自测 → 联机端到端
```

其中联机部分会真的起一个服务器 + 两个 Godot 客户端打满 12 回合，
逐回合把客户端的本地重放结果和服务器的状态快照对账。

改动规则必须**两个引擎一起改**（`scripts/core/turn_resolver.gd` 与 `train/engine.py` 是同一套规则的镜像），
不一致时不会报错，只会表现为 AI 打得莫名其妙，所以对拍是硬门槛。

`export_parity.py` 里有一份定向牌对清单，专门保证随机跑不到的规则交叉点也被覆盖。

## 目录

```
darkcard/
  data/cards.json              50 张卡表（唯一数据源，含可被列与机制字段）
  scripts/core/                规则内核：结算管线、卡牌结构、状态、合法性判定
  scripts/ui/ scripts/ai/      界面与 AI
  scripts/net/                 联机客户端：HTTP 通道、对局会话、单机/联机统一控制器
  scenes/main/ scenes/lobby/   主菜单与联机大厅
  server/                      联机服务器（纯 Python 标准库）+ 部署文档
  train/                       规则镜像引擎、自博弈训练、对齐/对拍/不变量工具
  tests/ tools/                规则单测与校验工具
暗牌技能对战_立项包/            策划案、技术方案、规则风险清单与变更补丁
```

## 训练

`train/trainer.py` 是自博弈强化学习训练器，策略网络结构见 `train/policy_net.json`，
`train/watch_games.py` 可把对局逐回合打出来看。检查点不进仓库。
